# v1.3.1 更新細節

v1.3.1 保留 Unit、TUnit、Integration、Aspire 的四套 1＋4 架構，固定依序執行 Analyzer、Writer、Executor、Reviewer。主要更新是四套完整的實際 token 用量 HTML、Standard credit 換算與絕對路徑交付，以及 runtime 隔離、收尾、交接與環境前置檢查修正。

## 實際用量 HTML

四套各自提供用量收集、HTML renderer 與 observer，不跨 workflow import。報告涵蓋本次主代理及子代理，列出未快取輸入、快取輸入、輸出、含快取總量與請求數；依明確 root turn、代理關係與 response ID 歸屬及去重，保留正式修正回合。

啟動時建立等待頁，主代理回合結束且連續三次快照一致後更新同一份 HTML。頁面可離線開啟；收集期間可重新整理。最終回覆尾端提供可點擊的絕對檔案路徑、可複製的原生絕對路徑及 file URL，方便直接開啟報告。

收集需要可讀的 Codex session 與受支援的 state SQLite schema。優先使用 Node 內建 SQLite 唯讀介面，現有 Python 3 為備援，不自行安裝依賴。缺漏、不支援、中止、逾時或 observer 失敗均如實呈現，不補零、不改寫測試結果或耗時；`unsupported` 沒有啟動背景程序，重新整理不會恢復收集。

## Standard credit 換算

HTML 可展開選用 credit 區塊，依每個代理實際記錄的模型及設定換算。新增 `gpt-6.1-sol`，保留既有 `gpt-6-sol`、`gpt-6-luna`、`gpt-6-astra` 與其他受支援模型；費率採本版 2026-10-07 快照，詳見 [用量指南的模型費率表](token-usage-estimation.md#standard-credit-試算與模型支援)。

GPT-6.1 Sol 每百萬未快取輸入／快取輸入／輸出為 50／2.5／250 credits；三欄各一百萬 tokens 的試算為 302.5 credits。推理已含於輸出，不重複加總或依推理強度另乘倍率。服務模式缺漏時標為 Standard 前提試算，未知模型、非 Standard 模式或缺漏用量不提供合計。

此功能適用 ChatGPT token-based credits 的公開費率試算，不適用 API key 或舊制企業方案，也不代表企業帳戶實際扣抵。正式 Orchestrator 與四角色仍維持 `gpt-5.6-sol／medium`；增加模型換算支援不會自動變更正式 profiles。

## 四套流程修正

| 工作流程 | v1.3.1 修正內容 |
|---|---|
| Unit | 自有 run-state、validators 與完整用量模組；NuGet preflight；Coverage 簡名與唯一完整型別名稱比對；後續 blocked 終態保留已完成 Writer 產物與測試事實；七區塊及回覆尾端 HTML。 |
| TUnit | 自有 run-state、validators 與完整用量模組；方法識別交接一致；gate 拒絕後 deterministic closeout 與 canonical renderer；保留 TUnit 自有 build／run、七區塊及原始終態。 |
| Integration | runtime 隔離；完整 HTML 自動交付；執行證據、情境交接、耗時與顯示契約修正；保留 endpoint 範圍與 Executor 原始測試結果。 |
| Aspire | 完整 HTML 與 canonical renderer；Docker daemon／NuGet 前置檢查；Analyzer、Writer、Executor、Reviewer 交接及證據契約修正；保留八項回報、固定四階段與既定環境例外。 |

四套保留每 target 單一 Writer，承接所有有效情境；不依情境數拆分 Writer。Executor 是 build／test truth，Reviewer 仍必須執行。原 gates、Coverage 門檻、run-state 官方耗時與最終報告欄位維持既定契約。

## NuGet、Docker 與安裝

四套在 Analyzer 前各自執行 NuGet sandbox preflight，以實際 restore 判定環境。`NUGET_PACKAGES` 維持選用；未指定時沿用原 NuGet 設定與預設快取，不要求手改設定或提供額外 CLI NuGet override。Aspire 另核對 Docker daemon。

Unit／TUnit 依本次工具政策處理必要單次核准；保留各自正式 runner、attempt、原失敗與既定重試上限。政策不允許、核准遭拒或環境仍不可用時停止並保留診斷，不自行更改全域設定或擴大重試。Integration／Aspire 保留各自執行契約，不能把 Unit 的 runner 套用到其他框架。

installer 預設只安裝至目前專案 `.codex/`，保留既有設定；必要鍵衝突時在寫入資產前 fail closed。不再無條件覆寫使用者層 `~/.codex/config.toml`，不加入或覆寫選用快取、不預設開啟 sandbox 網路。

## 升級方式

依 [README 的安裝步驟](../../README.md#安裝與環境設定) 或 [環境設定指南](../SETUP.md) 更新整套公開資產，包括 `.codex/agents/`、四個 Orchestrator、`.codex/scripts/dotnet-testing-codex-full/` 與專案設定；不要只替換單一 Skill 或 runtime 檔案。公開內容共 16 個 Agent、5 個內建 Skill、59 支 runtime scripts，Full 與四套 owner 各自具備 asset manifest。

外部技術型 Skills 鎖定 `dotnet-testing-agent-skills v2.4.5`（commit `a4908967ef8fe63ad2fe275df1df3c015ec51a4c`），29 個 Skill 名稱與數量不變，由消費端另行安裝至 `.agents/skills/`。可選 `unit-test-scenarios` 仍使用鎖定的公開來源，兩者都不內含於本產品。

Unit 可沿用既有測試與建置產物作執行起點；其他三套的驗證起點依各自正式契約。生成測試、測試專案修改、`.orchestrator/`、`bin/`、`obj/` 與 `TestResults/` 都是執行產物，不納入公開發布。

## 驗收範圍

四套完整流程及最終結果呈現均完成人工驗收；新增 GPT-6.1 Sol 換算與絕對路徑功能另依序完成 Unit、TUnit、Integration、Aspire 驗收，核對實際產生 HTML 的換算程式與交付路徑。實際流程仍使用既定 profiles，合成費率核對不代表以 GPT-6.1 Sol 執行四角色或企業帳務驗證。

Aspire 流程修正另完成 .NET 10／9／8 指定情境驗收，最後測試結果分別為 13／0／0、22／0／0、12／0／0（passed／failed／skipped）。.NET 8 未使用 using 警告經使用者接受，保留 `pass_with_warnings`；歷史失敗、中間修正與原始測試數字保留，不將不同情境的結果混算。

靜態、契約與 deterministic 檢查是前置檢查，不替代人工 workflow 驗收。不宣稱所有平台與任意消費端環境均已驗證，也不宣稱實際 token 節省。CLI total 只涵蓋主代理未快取 input 加 output，HTML workflow 總量包含子代理與快取；兩者範圍不同。
